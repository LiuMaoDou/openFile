# FileM 开发计划与验收标准

日期：2026-09-12。状态：0.1.0 验证版已实现 M0/M1 的范围扫描、持久化与聚合浏览基础，并按本次补充要求加入单文件/批量回收站删除、确认清单、逐项日志与取消。当前实现与运行说明见 [README](../README.md)，已执行的测试见 [开发验证记录](FileM_开发验证记录.md)。下文仍是完整里程碑和验收目标；Windows 专项验证、增量恢复、复制/移动/重命名与重复检测尚未完成，不能把原型测试等同于全量验收。

设计依据：[FileM_方案审查与修订.md](FileM_方案审查与修订.md)。原始范围：[FileM_原始需求.md](FileM_原始需求.md)。

## 1. 交付目标与约束

第一个正式可用版本应让用户完成：**选择范围 → 查看所有同类文件及真实目录 → 筛选和预览 → 多选 → 预览真实操作 → 执行并核对结果 → 检查重复副本**。

建议首个验证平台为 Windows 11 x64、普通用户权限。Windows ARM64、旧系统及其他平台暂不承诺；macOS 上完成界面演示不能代替 Windows Shell 与文件系统验证。这是排期假设，并非用户已经确认的系统清单。

开发中使用专用测试目录和可重建文件集验证写入操作。应用只索引明确选择的范围，不预先读取用户的下载、文档或全盘。源文件操作与索引变化分开验证；不能用“界面行消失”证明文件已正确移动或回收。

首版不包含：全文检索、云同步、系统 Shell 替代、自动版本裁决、静默覆盖、自动永久删除、MFT/USN 提权加速。完整系统菜单与原生拖拽属于独立兼容阶段，不能用未实现的按钮充当能力。

## 2. 里程碑与工作量

以下是单名熟悉 Rust、Windows API 和前端的工程师的初步工作量区间，假设 Windows 测试环境、构建工具和测试文件集可用。它们是排期估算，不是性能实测或交付承诺。遇到 Shell/网络盘兼容问题时，应在 M0 后重新估算。

| 阶段 | 交付内容 | 依赖 | 估算工作日 | 完成门槛 |
| --- | --- | --- | --- | --- |
| M0 技术验证 | 扫描、监听恢复、身份、存储、Tauri 列表与 Shell 桥接原型报告 | Windows 环境 | 4–6 | 决定是否继续首选技术路线，冻结基准和关键语义 |
| M1 聚合浏览 | 范围管理、持久化、启动核对、类型导航、分页虚拟列表、打开/定位 | M0 | 8–12 | 文件集合与独立盘点一致；范围、离线和重启行为通过 |
| M2 批量操作与预览 | 多选、计划、复制/移动/回收、单项重命名、取消、结果与恢复、受限预览 | M1 | 8–12 | 成功、失败、取消、崩溃和冲突逐项可核对；无静默覆盖 |
| M3 重复检测与分类配置 | 完整哈希分组、保留副本选择、复用操作计划、自定义扩展名分组 | M1、M2 | 5–8 | 变化文件、占位、硬链接不误报；清理前保留副本有效 |

| M5 进阶能力 | 原生菜单/拖拽、模板重命名、MFT/USN，各自独立交付 | M4 或对应核心能力 | 另行评估 | 不以单个 API 调用成功替代端到端验收 |

M0–M4 合计约 29–45 个工程工作日，即约 6–9 周的净工作量；不包含签名采购、外部等待和兼容性返工。M1 可以先提供内部试用，M2 开始验证主要批量处理价值，M3 后具备首个完整使用闭环。原稿建议的一到两周现成工具试用可与 M0/M1 并行，不阻塞技术验证。

M0 完成后应记录：最低 Windows 范围、持久化路线、范围归属规则、性能基线与验收门槛。当前文档已给出推荐默认值，开发中的常规实现选择不需要逐项重新向用户请求确认；只有改变产品语义或支持范围时才集中讨论。

## 4. M1：可靠聚合浏览

按依赖顺序实施：

1. 稳定 ID、原生路径表示、范围成员规则和查询版本。
2. 范围配置增删改、目录选择、排除预览、递归与监听开关。
3. 可取消的目录遍历、目录失败区域记录、扫描代次与流式进度。
4. 持久化事务、索引加载、待校验状态与完整元数据核对。
5. 监听事件协调、目录移入/移出/更名、溢出恢复和配置失效处理。
6. 类型导航、后缀筛选、范围筛选、名称/路径/大小/日期过滤与排序。
7. 后端分页与稳定排序、前端虚拟列表、键盘导航和范围状态。
8. 打开、在资源管理器中定位、复制路径、从视图隐藏与恢复显示。

界面需要实际覆盖空范围、扫描中、无匹配、离线、拒绝访问、部分扫描、恢复中、查询失败等状态。默认显示目录；同名文件通过路径和范围区分。扫描中计数是已发现数量，不能用未经计算的百分比表现进度。

模块输出建议：纯规则与模型、Windows 平台访问、索引协调器、查询服务、持久化、Tauri 命令层、UI。目录结构随实际工具链确定，不在审查阶段生成空项目或依赖锁文件。

M1 验收：完整扫描与文件系统静止后的独立清单一致；重复添加根不重复索引；同一项跨范围不重复显示；移除范围不改变文件；离线仍可查旧索引；退出期间的深层变化在重新核对后补齐。

## 5. M2：真实批量操作和受控预览

### 5.1 操作计划

计划包含操作 ID、冻结选择、索引代次、来源身份与版本、原路径、目标路径、冲突处理、占位状态和可预估大小。界面先显示原位置到目标位置，再提交执行；生成预览本身不写源文件。

首版覆盖单项重命名、批量复制/移动、放入回收站，提供跳过冲突或生成不冲突名称。重名不能默认覆盖。目标位于范围外时，保持本次明确目标授权，不扩展索引范围。

跨目录选择、Shift 连选、Ctrl 多选、筛选后全选、排序后选择、分页跨页选择都使用稳定 ID。选择全部匹配项时冻结查询结果或建立等价的后端选择，展示实际计数；不能把页面可见数当成总选择数。

### 5.2 执行与恢复

通过 STA 通道执行 Shell 操作，逐项记录成功、失败、跳过和取消；执行后更新实际来源/目标及受影响索引。取消不回滚此前已完成项。应用崩溃后扫描未完成计划的实际状态，只展示可核实结果，不自动重放。

恢复移动或更名时检查当前身份与目标冲突。复制恢复需要确认目标仍是这次生成且未被外部修改的文件；否则不自动回收。系统回收恢复、跨卷移动恢复不承诺无条件成功，分别验证和展示支持边界。若系统将回收降级为永久删除，应在执行前中止该项，不以“用户点过删除”推定允许永久删除。

来源预检与 Shell 实际执行之间仍可能发生竞态：在进度回调的可行检查点复核，并缩小时间窗口。不能承诺仅靠一次路径存在检查就防止任何并发替换；在测试发现无法安全确认的场景中停止执行或改用更严格的句柄级方案。恢复能力由实际证据决定。

### 5.3 预览

先支持常见本地图片和有限长度文本；随后接入 PDF、音视频的明确支持格式。大图片设像素和内存上限，大文本截断并提示；任务可取消，缓存有容量限制。HTML/Markdown 文件内容按文本或受限渲染处理，不执行其中的脚本。PSD/RAW 等不承诺完整解析，可显示系统图标与基本信息，后续再加入经验证的缩略图提供者。

占位/离线/权限拒绝项不触发自动内容读取，使用状态卡片。用户明确请求读取云内容时先展示可能取回的文件。首版不提供自动批量生成全库缩略图。

M2 验收必须直接核对磁盘结果、文件身份、预期路径与测试文件内容；不能只查看通知条或列表计数。

## 6. M3：去重与分类配置

依次完成大小分桶、硬链接识别、流式完整哈希、稳定性校验、重复组展示、用户指定保留副本、复用 M2 的操作计划。哈希缓存以可验证身份与版本绑定，不能只用路径和大小命中。

对大小相同但内容不同、哈希过程中变化、占位、不可访问和硬链接分别提供测试。破坏性处理前复核保留副本可用且仍匹配；无法确认的文件保留原位并解释原因。默认数据流相同与“整个 NTFS 文件所有元数据相同”分开表述。

扩展名分组允许增加、删除、重命名和编辑后缀；修改后立即更新分类，数据总数不被多组交集重复累计。未归类与无扩展名始终有入口。规则导入/导出可在核心配置稳定后增加。

疑似版本识别暂列后续能力：需要展示命名、目录、时间等证据并由用户选择主版本，不按“最终版”或最新 mtime 自动整理。优先级低于完全重复检测。

## 8. 性能验证方法

### 8.1 数据集

| 数据集 | 用途 | 条件 |
| --- | --- | --- |
| S1 万级 | 功能和回归主集 | 混合后缀、中文、同名、嵌套、排除、已知内容校验值 |
| S2 十万级 | 首个性能门槛 | 单层密集与深层树两种分布，热缓存与可控冷缓存分开 |
| S3 百万级 | 压力与优化依据 | 先验证数据集准确性；不把 S2 数据线性外推为成绩 |
| S4 SMB/外置盘/云占位 | 兼容与降级 | 分别记录提供者/设备、延迟与能力，不与本机 SSD 混合统计 |

数据集生成与破坏性测试只在专用夹具中执行；真实用户样本仅在用户明确指定后用于相应操作。预览/哈希的内容样本不能用全为零字节的文件代替。

### 8.2 建议的初始体验目标

这些是 M0 用来判断方向的候选门槛，尚未承诺可达。M0 后在固定设备、release 构建、指定数据集上冻结版本验收标准；若不达标应定位、优化或明确缩小支持范围，不能用降低计量标准制造通过。

| 指标 | 候选目标/测量口径 |
| --- | --- |
| 已缓存十万项的首屏 | 主窗口可交互后 500 ms 内显示首个数据窗口；进程启动到可交互另行计时 |
| 热查询首个结果窗口 | 常用后缀/范围/名称组合 P95 ≤ 200 ms，包含 Rust 查询、IPC 和页面更新 |
| 十万项常用排序 | 首页更新 P95 ≤ 500 ms；记录不同排序字段和比较器成本 |
| 滚动 | 60 Hz 屏下以约 16.7 ms/帧为目标，报告 P95 帧时间及长任务；不靠主观“顺滑”验收 |
| 操作反馈 | 用户点击后 200 ms 内出现已接收/准备中的反馈，不承诺磁盘动作在此时间内完成 |
| 常规监听可见延迟 | 本机轻负载下事件至界面更新 P95 ≤ 1 s；风暴恢复单独测试 |
| 完整扫描/恢复 | M0 测定万级/十万级基线后冻结门槛；冷/热、SSD/SMB 分别报告 |
| 内存 | 报告索引、扫描峰值、预览缓存及关联进程总峰值；M0 后制定预算，删除原稿 10–50 MB 承诺 |

扫描和恢复至少重复 5 次，记录中位数和最差值；声称 P95 的短操作在固定负载下至少采集 100 个样本。百万级排序与 MFT 加速保持独立基准，不沿用未经验证的百毫秒结论。

报告必须附上构建版本、设备、文件集、操作脚本或步骤、时间测量点、内存统计方法、异常日志与结果清单。清单比较至少覆盖路径、成员、逻辑大小和 mtime；专用内容测试再比较实际文件字节。

## 9. M5：完整功能路线，按收益分批加入

| 工作包 | 价值 | 前提与验收 |
| --- | --- | --- |
| M5-A 原生菜单与文件拖拽 | 补齐与资源管理器协作 | 正确 Shell 项集合、STA/消息处理、跨目录和扩展测试，T25–T26 |
| M5-B 批量模板/正则重命名 | 减少重复手工处理 | 复用操作计划，处理重名、循环、保留名、预览与恢复，T28 |
| M5-C 整卷 MFT/USN | 优化超大整盘首次扫描与续读 | 受限提权、版本解析、硬链接路径、日志不连续与持久游标原子性，T27 |
| M5-D 快照/紧凑存储 | 降低已测出的内存或存储瓶颈 | 与当前实现使用相同数据集、持久性与查询负载比较，不跳过恢复校验 |
| M5-E 疑似版本、RAW/EXIF 等 | 面向明确的垂直使用需求 | 先选择一个高频场景，验证操作价值后单独定范围；不同时展开 |

M5-C 的目标是优化受支持的整卷场景，不取代无管理员权限的目录路径。M5-D 只有在基准证明需要时才启动，不能因为原稿提到字符串池和二进制格式就优先实现存储引擎。

## 11. 发布时必须交付的证据

交付 Windows 安装/启动产物、明确的系统支持清单、应用版本与构建记录、验收矩阵结果、可复现的性能报告及已知限制。对“恢复”按动作明确说明支持范围；无证据的功能不能宣称已支持。

实现阶段完成与改动相关的 Rust 测试/检查、前端类型检查和构建，以及真实 Windows UI/Shell 操作验证。浏览器控制台或应用日志存在阻断错误时，不签署界面验收。只修改文档时无需搭建应用测试环境。

当前已交付首个开发验证版本，下一阶段优先补齐 Windows M0 与回收站实机证据、增量恢复和查询快照，再扩展其余批量操作。MFT、存储替换和完整系统菜单继续按后续里程碑安排。
