# FileM 0.1.7：扫描进度与扫描性能优化

本版适用于 Windows x64 和 macOS Intel。监控文件夹、隐藏记录和已有内容索引继续保留，无需清空索引；安装前请退出旧版 FileM。

## 看得见的扫描进度

- 扫描时显示进度条、已处理/已发现目录数、当前位置与耗时。
- 百分比表示已发现目录的处理比例。目录总数随扫描更新，并非事先统计完整磁盘后的固定总数。
- 目录遍历完成后显示“正在整理索引”，提交完成后才显示“扫描完成”。
- 支持浅色、暗色与跟随系统主题；进度更新不会重复触发文件检索。

## 减少重复扫描与等待

- 普通文件新增、修改、删除和改名合并为按路径更新，减少整个监控文件夹的重复扫描。
- 合并多个目录的数据库写入，未变化的元数据不重复更新；保持原有事务与文件身份校验。
- 查询、状态统计与扫描写入使用独立数据库连接，读取一致的已提交结果；未变化的统计结果按索引版本复用。
- 目录变化、监听丢失事件、启动和手动刷新仍会完整核对。无法读取的路径保留旧索引和处理说明。

本机 Intel Mac 的 10 万个临时文件、100 个目录测试中，重复全量核对平均约从 7.5 秒降到 3.0 秒；首次扫描约 5.6 秒，基本不变。该数据为本地元数据测试，不代表 Windows、网络盘、正文提取或整盘扫描性能。

## 使用建议与验证边界

整盘扫描会包含大量系统、应用与缓存文件。优先添加常用资料目录，按需要设置排除规则；Windows 可运行 Everything 1.4 标准版，并启用 FileM 中的“Everything 加速”。正文索引建议只对需要全文搜索的资料文件夹开启。

本地已通过 58 项核心/集成测试、内容提取冒烟测试、TypeScript/Vite 构建、Rust 格式与严格 Clippy 检查。浏览器使用 10 万个临时文件验证真实进度、扫描完成与文件名搜索，并验证浅色/暗色、1440 和 900 像素宽窗口；暂停和整理阶段另有受控状态检查。Windows 安装、网络盘和云占位文件等仍需目标环境验收，GitHub Actions 结果以本次提交为准。

macOS 包未使用 Apple Developer ID 签名且未经公证；首次打开如被拦截，可在确认下载来源后进入“系统设置 → 隐私与安全性 → 仍要打开”。Windows 包未做代码签名。
