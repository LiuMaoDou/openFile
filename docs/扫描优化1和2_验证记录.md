# 扫描优化 1 和 2：实现与验证

本次改动针对 Windows 与 macOS 共用的 Rust 扫描核心，沿用现有数据库和设置，不需要清空索引。

## 1. 减少重复数据库操作，让读取和写入重叠执行

- 文件信息按 256 条传递，经有容量上限的队列送往写入线程，按 512 条提交事务。大目录不再必须收集完所有文件信息才能开始写入。
- 在一批事务中复用 SQL 语句和最近目录 ID；已有文件一次查询同时判断身份和元数据是否变化，避免重复查询文件 ID。
- 未变化的文件不执行元数据 UPDATE。发现同一路径被另一个文件替换时，仍使旧 ID 和隐藏状态失效，并保留其他扫描范围的关联关系。
- 每个路径只计算一次排除规则，同时得到文件和目录的收录条件。
- 文件移动、删除需要的暂停覆盖读取线程、队列和数据库提交；恢复时重新核对被中断的批次。读取异常仍保留对应路径的旧索引。

## 2. 共用线程池，合并重叠范围并按卷调度

- 沿用全局 4 个读取工作线程；同时最多运行 4 组扫描。同卷的扫描组排队，不同卷的扫描组可以并行，避免每个文件夹各自扩张线程池。
- 同时等待全量核对的父子范围合并为一次目录遍历。读取到的文件信息只写入一份文件记录，再更新符合条件的各个范围的关联关系。
- 每个范围独立执行排除规则、递归设置、进度更新、取消和配置版本检查；父范围排除的目录，仍可被单独添加的子范围收录。
- 合并只针对尚未领取的全量扫描请求；已经开始后收到的新变化仍会再次核对，避免把扫描期间的变化误认为已处理。
- 同卷判断采用监控根目录现有的设备/卷标识。不同分区、嵌套挂载和网络共享的底层物理设备关系并未完整建模。

## 正确性验证

新增 10 项测试，覆盖：父子范围只遍历一次、不同排除规则和非递归范围、待扫描请求合并、取消某个成员、配置中途变化、取消后的最终提交、稳定文件零元数据更新、替换文件保留其他关联、写入失败解除队列阻塞、暂停后重新核对，以及同卷限流与独立卷准入。其中部分测试同时验证多个关联行为。

核心与集成测试共 68 项通过；TypeScript/Vite 构建、Rust 全工作区检查、严格 Clippy、格式检查和 `git diff --check` 均通过。Windows x64 全工作区及全部目标交叉编译检查通过。原生 PDF/DOCX/XLSX/PPTX 提取、中英文全文检索和关闭索引后的清理冒烟测试通过。

Windows 检查最初因命令缺少 LLVM 路径而找不到 `llvm-lib`，补齐现有工具链路径后通过；未修改源码绕过检查。Windows 桌面运行、安装及实机性能未在本轮验证。

## 性能测试方法

- 基线是 `0355e40faff59fb8be854dbb11998b99fc8d8a9a` 的扫描算法，优化版保持相同的 4 个读取工作线程，均使用 release 构建。
- 使用临时生成的 100,000 个小文本文件：4 个 `group0` 至 `group3` 目录，各含 25 个子目录，每个子目录 1,000 个文件。
- 目录树测试添加共同父目录；多范围测试同时添加这 4 个同卷目录。另外生成 100,000 个文件集中在单个目录的样本。均关闭实时监听和正文索引。
- 每个进程独立创建临时数据库，执行一次首次扫描和三次全量刷新，并校验检索结果为 100,000 个文件。对比交替运行两轮；第二轮颠倒新旧顺序。
- 耗时包含 200 毫秒请求合并等待和约 100 毫秒一次的状态轮询。样本创建后反复使用，未控制冷缓存，不是整盘、正文提取、前端渲染或 Windows 实机性能测量。
- 同时保留进程 CPU 时间、峰值 RSS 和每轮原始耗时。调度的不同卷并行已做受控单元测试，实际多磁盘吞吐仍需目标设备测量。

## 最终性能结果

以下为每种实现 6 次重复全量核对的中位数，括号内是最小值至最大值。首次扫描只用于建库，不纳入速度对比。

| 场景 | 原版重复核对 | 优化版重复核对 | 本轮中位数降幅 | 原版 / 优化版峰值 RSS 中位数 |
|---|---:|---:|---:|---:|
| 一个目录树（100 个子目录，另有 4 个分组目录） | 6.63 秒（4.97–12.45） | 5.27 秒（2.94–9.39） | 21% | 63.1 / 23.1 MiB |
| 同时提交 4 个同卷目录 | 7.67 秒（6.34–14.34） | 3.94 秒（2.51–4.89） | 49% | 96.7 / 24.1 MiB |
| 单个目录集中存放全部文件 | 6.42 秒（4.61–9.64） | 1.89 秒（1.57–4.36） | 71% | 114.0 / 23.4 MiB |

本轮绝对耗时存在明显波动，尤其目录树场景的新旧范围重叠。表中降幅描述这批样本，不能视为所有设备的固定提速比例。单大目录与同卷多目录的优化后刷新样本均低于对应原版样本；峰值内存下降在三种结构中都出现。
