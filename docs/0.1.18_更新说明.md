# FileM 0.1.18 · 修复版本号等关键词的误匹配（Windows）

本版本基于 [0.1.17](https://github.com/LiuMaoDou/openFile/releases/tag/v0.1.17)，修复空格分隔搜索中，单个关键词被进一步拆分而导致的误匹配。

## 搜索修复

0.1.17 将关键词匹配设为默认，但沿用了会拆分标点和连续中文的查询分词规则。例如 `中期 1.2` 中的 `1.2` 会被拆成 `1` 和 `2`，文件名中的 `V1.0` 与日期中的 `2` 因而可能共同满足查询。

0.1.18 的查询只按空格、制表符等空白字符分隔。每个关键词作为完整的字面子串匹配，所有关键词都必须命中（AND）；点号、下划线、路径分隔符、连字符等符号以及连续中文均保留。关键词顺序不限，首尾空白、连续空白和重复关键词会被忽略，英文不区分大小写。

在“文件名 / 路径”模式输入 `中期 1.2`，且所在目录路径不含 `1.2` 时：

- `IP网络集成服务V200R008 OBP 中期审视V1.0-20240106.pptx` 不再命中，因为名称与路径均缺少完整的 `1.2`。
- `IP网络集成服务V200R008 OBP 中期审视V1.2-20240106.pptx` 可以命中，因为名称同时含有 `中期` 和 `1.2`。

“文件名 / 路径”仍允许不同关键词分别命中文件名和所在目录；如果所在目录本身含有 `1.2`，名称含 `中期` 的文件也会命中。选择“文件内容”时，全部关键词须在已提取正文中出现；“文件名 + 内容”仍要求名称/路径或正文一侧满足全部关键词。

连续中文也按输入保留：`项目合同` 要求这四个字连续出现，若要分别匹配则输入 `项目 合同`。需要把含空格的整段短语连续匹配时，仍可选择“精确匹配”。默认相关度排序及单次最多 32 个词的限制继续适用。

## 升级与内容索引

本次修复调整查询关键词的拆分方式，已有正文和词索引可直接使用，无需重新提取文档或重建索引。文件内容搜索仍只覆盖已开启索引并完成提取的正文；文件夹设置、隐藏记录、列布局和文件操作功能继续保留。

发布前的回归验证范围包括：上述 `1.0` / `1.2` 文件名案例、含标点与连续中文的完整关键词、空白与词序处理，以及已有内容词索引和字面匹配兜底两种查询路径。实际构建与测试结果以对应的 [GitHub Actions 记录](https://github.com/LiuMaoDou/openFile/actions) 为准。

## Windows 发行包

- Windows x64 安装版：`FileM_0.1.18_x64-setup.exe`。
- Windows x64 便携版：`FileM-0.1.18-windows-x64-portable.zip`。
- `SHA256SUMS.txt`：安装版与便携版的 SHA-256 校验值。

下载与校验值见 [v0.1.18 Release](https://github.com/LiuMaoDou/openFile/releases/tag/v0.1.18)。便携版完整解压后运行 `FileM.exe`，依赖系统 [Microsoft WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)；安装版由 Tauri 安装流程处理 WebView2。使用者无需安装 Node.js、Rust 或 Visual Studio。

安装包尚无代码签名；Windows 实机交互与多磁盘场景仍需验证。CI 编译与测试通过不等于所有实际设备均已验收。本次仅发布 Windows x64 安装版与便携版。
