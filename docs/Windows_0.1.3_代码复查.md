## 继续核对的约束

- 所有真实文件操作均由文件 ID 找到原生路径，再复核身份、大小、修改时间和有效文件夹。显示用的 `D:\` / UNC 字符串不用于 Windows 原生文件 I/O。
- 删除与移动使用各自的单次计划和持久化逐项日志，并串行处理真实文件变更。取消只停止后续项目；中断项不自动重试。
- Windows 回收使用 `IFileOperation`，在进度回调中拒绝永久删除，并核对回收结果。打开和定位使用经身份核对的 Shell item / PIDL。
- 移动不覆盖已有目标；移出所有监控文件夹后仅移除索引引用。同名冲突、身份变化、文件不可访问均有逐项结果。
- Everything 使用官方静态 SDK，通过单独辅助进程调用 IPC；只接收当前监控文件夹内的候选，查询未连接、失败、超时、忙碌或结果过多时回退。
- 文件夹统计通过成员关系去重；旧统计和旧搜索响应不会覆盖新的选择。文件表格的事件绑定稳定文件 ID，行尾按钮不会触发整页重新加载。
- 开发服务只监听回环地址，启动令牌不写入前端；代理拒绝外站 Origin。预览文本以文本渲染，SQL 值使用参数，排序字段使用白名单。
- 发行版资源包含图标与 Everything SDK 的许可；仓库不含索引、用户测试目录、构建缓存或发行包。

## 尚需目标环境验收

实际 Windows 11 桌面中的系统应用启动、Explorer 定位、原生目录选择、跨磁盘移动、UNC/网络盘、长路径、junction、OneDrive 占位、权限变化与不同文件系统仍需要验收。CI 的本地 NTFS 临时目录不能替代这些场景。

最终复核与系统路径操作之间仍存在其他进程改变文件的竞态窗口；不宣称能抵御恶意进程在最后一刻替换路径。百万文件性能、USN/MFT 增量监听与断线自动重连仍属于后续开发范围。
